# Epic Quality

An Epic coordinates several deliverable slices toward one measurable outcome.

## Qualification

| Requested work | Result |
| --- | --- |
| opportunity or product bet | Product Brief |
| one independently deliverable behavior | User Story |
| bounded delivery work without independent value | Task |
| one bounded uncertainty | Spike |
| several outcomes that can succeed independently | split Epic candidates |
| one outcome requiring several deliverable slices | Epic |

## Readiness

| Criterion | Ready when |
| --- | --- |
| Outcome | one observable change is named |
| Goal | an existing Product Brief or product goal is linked, or none applies |
| Context | audience, need, and value are supported or marked as assumptions |
| Boundaries | included and excluded work constrain the outcome |
| Success | evidence can confirm or challenge the outcome |
| Relations | source, dependencies, and blockers are linked or absent |
| Unknowns | each is accepted, deferred, or assigned a Spike |

An Epic may be persisted as `proposed` before it is ready. It becomes `ready` only when every row passes.
