# Readiness

| Criterion | Ready when |
| --- | --- |
| Outcome | one observable change is named |
| Goal | a resolvable Product Brief or product goal is linked, or the field is absent |
| Context | audience, need, and value are supported or marked as assumptions |
| Boundaries | included and excluded work constrain the outcome, supported or marked as assumptions |
| Success | evidence can confirm or challenge the outcome |
| Relations | source, dependencies, and blockers are linked or absent |
| Unknowns | each is accepted, deferred, or assigned a Spike |

An assumption is accepted once it is stated to the user and left uncontradicted; it is recorded under `Dependencies and Unknowns`. Anything else is inference.

An absent goal does not block readiness; backlog review asks about alignment on its own.

An Epic may be persisted as `proposed` before it is ready. It becomes `ready` only when every row passes.
