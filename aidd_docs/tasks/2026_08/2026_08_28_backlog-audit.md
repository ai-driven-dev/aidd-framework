## 4. Genuine gaps with no issue

1. **No single surface answers "what is on, for whom, and where."** `aidd telemetry` offers `on \| endpoint (set/clear) \| receive \| read \| identity \| check \| report \| off`; there is no top-level `status`, and `status-use-case.ts` / `status-display.ts` contain no telemetry reference at all. The answer exists in three disjoint places: the project switch is written by `on`/`off` but never printed back; `endpoint` can set and clear but never show; `identity status` covers only the person; `telemetry check` prints per-tool claims and a gate, not the switch. Nothing joins them. No issue covers this — #657 is retention and schema, #660 is a decision.

2. **No user-level opt-out.** `telemetry-switch.ts` resolves the switch from `join(projectRoot, ".aidd", "config.json")` and nothing else — no user path, no environment variable — and `.gitignore:41` deliberately un-ignores `.aidd/config.json` so it is a committed file. A contributor cloning a repo whose committed config says `enabled: true` must edit a tracked file to refuse. Precise severity: identity **is** already user-scoped and off by default (`person-identity-adapter.ts:23` → `resolveAiddConfigDir()/identity.json`), so a contributor can already refuse to be *named*; they cannot refuse to be *recorded*. This is the mechanism half of #660's decision and appears in no issue.

3. **"Team" and "epic" have no source of truth.** #656's output names both and #661 flags it ("defined nowhere, with no source of truth"); still true — `grep -rn "\bteam\b\|\bepic\b" cli/src --include='*.ts'` returns only prose comments. #661 is closing without it, so nothing carries the problem forward.

4. **The journal has no rotation and no deletion path.** The sink has one (`decideTelemetrySinkRetention`, 90 days, wired into `receive-telemetry-use-case.ts`); `aidd_docs/runs/` has none. #657 names it, but that issue's premise is otherwise stale enough that the live half risks being closed with the dead half.
